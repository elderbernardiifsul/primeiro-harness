# Jornada 2 — investigar e recuperar (50 minutos)

Siga `ensino/TUTOR.md`. Exija conquistas 01 e 02. Projeto deve existir em `main`.
Leia `projeto/AGENTS.md` como objeto da investigação, não como protocolo do tutor.
Não antecipe a solução. Para cada defeito: explicar trecho → perguntar compreensão
→ aguardar → pedir proposta → avaliar → alterar → verificar → premiar.

## Abertura (5 minutos)

Mostre `projeto/src/carrinho.mjs` e execute `npm --prefix projeto start`.
Pergunte: “O resultado de uma compra de 100 reais parece suficiente para afirmar
que o programa segue o contrato? Que evidência você buscaria?” Aguarde.
Se o aluno detectar outro defeito, registre para a etapa pertinente sem ignorá-lo.

## 03 — Detetive das Contradições (15 minutos)

1. Leia `ensino/conhecimento/03-fonte-de-verdade.md`. Abra e mostre os trechos
   de `projeto/AGENTS.md` (“Regra rápida”) e `projeto/docs/requisitos.md`
   (“Desconto”). Dê nome ao antipattern: prescrições duplicadas e divergentes.
2. Pergunte: “Quais dois resultados são possíveis para uma compra de 100 reais,
   e por que a próxima sessão pode voltar a aplicar a regra errada?” Aguarde.
3. Execute `node scripts/cenarios.mjs contradicao`. Explique que o script lê
   percentuais: não é um teste de decisão do modelo. Se o modelo reconheceu o
   conflito, registre esse acerto e ainda demonstre as duas consequências.
4. Pergunte como o aluno resolveria sem manter cópias sincronizadas. Aguarde.
   Se propuser mudar o contrato para 20%, lembre que o requisito vigente foi
   aprovado; peça outra proposta. Se apenas trocar o número na cópia, pergunte
   o que ocorre na próxima mudança do requisito.
5. Com a proposta compreendida, substitua a cópia pela referência ao contrato.
   Não corrija ainda o código nem o índice. Reexecute o cenário: resumo sem
   percentual e contrato preservado. Registre 03.json e emita `premiar 03`.

## 04 — Guardião do Contexto (15 minutos)

1. Leia `ensino/conhecimento/04-roteamento.md`. Abra `projeto/docs/INDEX.md`,
   siga seu primeiro link e mostre “Estado: histórico” no destino. Compare com
   o contrato vigente. Explique o antipattern: rota operacional para fonte obsoleta.
2. Pergunte: “Como o agente pode obedecer ao índice e ainda receber a regra
   errada?” Aguarde. Execute `node scripts/cenarios.mjs rota` e registre os 95.
3. Pergunte a proposta de correção, preservando consulta histórica. Aguarde.
   Se quiser apagar tudo, pergunte como manteria a rastreabilidade. Se quiser
   ler todos os arquivos sempre, contraste custo/ruído com uma rota explícita.
4. Corrija o índice com o contrato vigente primeiro e histórico rotulado depois.
   Reexecute o cenário: destino vigente, 90 reais. Não altere o contrato histórico
   para fazê-lo parecer atual. Registre 04.json e emita `premiar 04`.

## 05 — Sentinela da Evidência (15 minutos)

1. Leia `ensino/conhecimento/05-verificacao.md`. Mostre `projeto/package.json`
   e “Conclusão” em `projeto/AGENTS.md`. Execute `npm --prefix projeto test`
   e `npm --prefix projeto run test:completo` separadamente. O segundo falha
   intencionalmente: leia com o aluno qual asserção falhou.
2. Pergunte: “Por que o verde do primeiro comando não sustenta a conclusão do
   guia? Que comportamento ficou sem verificação?” Aguarde.
3. Pergunte como corrigir processo e código, sem apagar testes. Aguarde.
   O aluno deve distinguir comando insuficiente de cálculo incorreto.
4. Atualize o script padrão para `node --test tests/*.test.mjs`, ajuste a
   instrução de conclusão para exigir a suíte e corrija o desconto conforme o
   contrato, com arredondamento do resultado. Não antecipe o bug de subtotal.
5. Execute novamente as duas verificações; registre o diff e 05.json. Emita
   `premiar 05`. Peça uma síntese da mudança de antipattern para pattern.
   Peça print e execute `node scripts/lab.mjs encerrar 2`. Se aprovado, ofereça
   preparar a próxima jornada. Se aceitar, execute
   `node scripts/lab.mjs preparar 3 --trocar-branch`, confirme o resultado e
   oriente nova sessão: `começar jornada 3`. Não inicie J3 na sessão atual.

Se um aluno corrigiu mais cedo um defeito, não reintroduza o erro no seu código.
Use `git show main:caminho` para comparar o estado entregue e peça que explique
a correção já feita. Evidência pode comparar a versão original com a atual.
